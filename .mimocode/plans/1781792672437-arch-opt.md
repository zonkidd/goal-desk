# 架构优化计划

## 当前核心问题

### 问题 1：`baseTimeline` 双重职责
- `eventkitStore.baseTimeline` 既存储 EventKit 原始数据，又被 `recomputeDerivedState` 写入派生后的 TodayAgenda
- 原始数据被覆盖后无法重新计算
- 违反"单一数据源"原则

### 问题 2：循环依赖风险
- `recomputeDerivedState` 写回 store → 触发订阅 → 再次调用 `recomputeDerivedState`
- 虽然用引用比较避免了无限循环，但逻辑脆弱

### 问题 3：`useAppStore` 性能陷阱
- 组件订阅所有 4 个 store 的完整状态
- 只使用 `state.currentView` 的组件也会在 `tasks` 变化时重渲染

### 问题 4：缺少批量更新
- 5 次独立 `setState` 调用，每次触发订阅和重渲染

---

## 优化方案

### 阶段 1：分离 baseTimeline（低风险，高收益）

**目标**：将原始数据和派生数据分开存储

**修改文件**：
- `src/store/eventkitStore.ts` — 重命名 `baseTimeline` → `rawTimeline`（原始 EventKit 数据）
- `src/hooks/useStoreComposition.ts` — 派生 timeline 存储到 `taskStore` 而非 `eventkitStore`
- `src/store/taskStore.ts` — 新增 `todayTimeline` 字段
- `src/store/appStore.selectors.ts` — 修改 `selectFilteredTimeline` 读取 `taskStore.todayTimeline`
- `src/store/appStore.ts` — 更新组合 hook

**数据流**：
```
EventKit → eventkitStore.rawTimeline（只读原始数据）
                    ↓
            WorkspaceEngine.computeTimeline()
                    ↓
            taskStore.todayTimeline（派生数据）
                    ↓
            TodayView 右侧时间轴
```

### 阶段 2：移除 useAppStore 组合 Hook（中风险，中收益）

**目标**：组件直接使用细粒度 store，避免不必要的重渲染

**修改文件**：
- `src/store/appStore.ts` — 保留便捷选择器，移除 `useAppStore` 组合 hook
- `src/components/` — 所有使用 `useAppStore` 的组件改为直接使用 `useTaskStore`、`useGoalStore` 等

**示例**：
```typescript
// 之前
const tasks = useAppStore((state) => state.tasks)

// 之后
const tasks = useTaskStore((state) => state.tasks)
```

### 阶段 3：批量更新派生状态（低风险，中收益）

**目标**：减少重渲染次数

**修改文件**：
- `src/hooks/useStoreComposition.ts` — 使用 Zustand 的批量更新

**示例**：
```typescript
function recomputeDerivedState(snapshot: WorkspaceSnapshot) {
  const taskStore = useTaskStore.getState()
  const goalStore = useGoalStore.getState()

  // 批量更新，只触发一次重渲染
  useTaskStore.setState({
    todayFocusTasks: snapshot.today.focusTasks,
    todayAttentionGroups: snapshot.today.attentionGroups,
    inbox: snapshot.inbox,
    todayTimeline: snapshot.today.timeline,
  })
  goalStore.updateTodayRelevantGoals(snapshot.today.relevantGoals)
}
```

### 阶段 4：统一响应式系统（高风险，高收益）

**目标**：移除 @preact/signals-react，统一使用 Zustand

**修改文件**：
- `src/app/signals.ts` — 移除 signal 定义
- `src/reactive/` — 改为纯函数（无副作用）
- `src/components/` — 移除 `useSignal` 调用

**注意**：此阶段需要全面评估影响范围，建议在阶段 1-3 稳定后进行
