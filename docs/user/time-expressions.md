# 自然语言时间表达式

Goal Desk 支持在快速捕获中使用自然语言描述时间，自动识别并设置任务的开始时间或截止时间。

## 支持的表达式

### 相对日期

| 表达式 | 示例 | 解析结果 |
|--------|------|----------|
| 今天 | 今天开会 | 今天 09:00 |
| 明天 | 明天评审 | 明天 09:00 |
| 后天 | 后天提交 | 后天 09:00 |
| N天后 | 3天后汇报 | 3天后 09:00 |
| 三天后 | 三天后汇报 | 3天后 09:00（支持中文数字一到十）|

### 相对星期

| 表达式 | 示例 | 解析结果 |
|--------|------|----------|
| 下周一 | 下周一开会 | 下周一 09:00 |
| 本周五 | 本周五提交 | 本周五 09:00 |
| 下周三 | 下周三下午2点 | 下周三 14:00 |

### 时间点

| 表达式 | 示例 | 解析结果 |
|--------|------|----------|
| HH:MM | 明天15:30评审 | 明天 15:30 |
| N点 | 明天3点开会 | 明天 15:00（智能识别为下午）|
| 三点 | 明天三点开会 | 明天 15:00（支持中文数字）|
| 下午N点 | 明天下午3点 | 明天 15:00 |
| 晚上N点 | 今晚8点健身 | 今晚 20:00 |

### 时间段关键词

| 关键词 | 默认时间 | 示例 |
|--------|----------|------|
| 早上/上午 | 09:00 | 明天上午开会 → 明天 09:00 |
| 下午 | 14:00 | 后天下午开会 → 后天 14:00 |
| 晚上/今晚 | 20:00 | 今晚健身 → 今天 20:00 |

### 截止时间

在时间表达式后添加"前"、"之前"或"截止"关键词，系统会将时间设置为截止时间而非开始时间。

| 表达式 | 解析结果 |
|--------|----------|
| 明天3点前提交报告 | 截止时间：明天 15:00，标题：提交报告 |
| 本周五之前完成 | 截止时间：本周五 09:00，标题：完成 |
| 3天后截止 | 截止时间：3天后 09:00 |

## 智能特性

### 1. 智能上下午判断
单独使用"N点"时，系统会智能判断上下午：
- 1-7点 → 自动识别为下午（+12小时）
- 8-23点 → 保持原值

示例：
- "3点开会" → 15:00
- "9点开会" → 09:00

### 2. 默认时间补充
- 只有日期没有时间 → 默认 09:00
- 只有时间没有日期 → 默认今天

### 3. 标题自动清理
时间表达式会从标题中自动移除，保持标题简洁。

示例：
- 输入："明天下午3点开会"
- 标题："开会"
- 开始时间：明天 15:00

## 使用示例

### 基础示例
```
明天开会                    → 开会 (明天 09:00)
后天下午评审                → 评审 (后天 14:00)
3天后提交报告               → 提交报告 (3天后 09:00)
```

### 精确时间
```
明天15:30开会               → 开会 (明天 15:30)
今晚8点健身                 → 健身 (今晚 20:00)
下周一下午2点面试           → 面试 (下周一 14:00)
```

### 截止时间
```
明天3点前提交               → 提交 (截止：明天 15:00)
本周五之前完成代码审查      → 完成代码审查 (截止：本周五 09:00)
```

### 中文数字
```
明天三点开会                → 开会 (明天 15:00)
三天后汇报                  → 汇报 (3天后 09:00)
```

## 注意事项

1. **时间表达式需要完整**：确保日期和时间关键词连在一起或距离较近
2. **一个任务一个时间**：每个任务建议只包含一个主要时间表达式
3. **中文数字范围**：目前支持"一"到"十"的中文数字
4. **优先级**：HH:MM 格式 > N点 > 时间段关键词 > 默认时间

## 技术说明

时间解析在 Tauri 端的 Rust 代码中完成，确保：
- 高性能解析
- 一致的行为
- 与本地 SQLite 数据库的无缝集成
