# Areas 重设计测试清单

本文档提供 Areas 功能的手动测试步骤，用于验证数据迁移、UI 交互和业务逻辑。

## 测试环境准备

### 选项 1：使用旧版数据库测试迁移

1. 备份当前数据库（如果有）
2. 使用 `src-tauri/tests/fixtures/legacy_db.sql` 创建测试数据库
3. 将测试数据库复制到应用数据目录
4. 启动应用

### 选项 2：使用全新数据库

1. 删除现有数据库（或重命名以备份）
2. 启动应用，将自动创建全新数据库

---

## 1. 数据迁移测试

### 1.1 旧数据库迁移

**前置条件**：使用包含孤儿 goals 的旧版数据库

- [ ] 启动应用
- [ ] 验证"未分类" area 自动创建
- [ ] 打开 Goals 视图，检查原本 `area_id = NULL` 的 goals 现在显示为"未分类"
- [ ] 检查原本 `area_id` 指向不存在 area 的 goals 现在显示为"未分类"
- [ ] 验证正常关联的 goals 的 area 没有改变

**预期结果**：
- Areas 视图中存在"未分类"领域
- 所有 goals 都有有效的 area 关联
- 原有数据（goals 和 areas）数量未减少

### 1.2 迁移幂等性

**前置条件**：已执行过一次迁移

- [ ] 关闭应用

- [ ] 验证"未分类" area 没有重复创建
- [ ] 验证 goals 没有被重复移动
- [ ] 验证 areas 数量保持不变

**预期结果**：
- 重复启动不会产生重复数据
- 数据状态保持一致

### 1.3 全新数据库

**前置条件**：使用全新的空数据库

- [ ] 启动应用
- [ ] 验证"未分类" area 自动创建
- [ ] 验证"未分类"是唯一的 area
- [ ] 验证没有 goals

**预期结果**：
- 自动创建"未分类"系统领域
- 应用可以正常使用

## 2. 创建 Goal 测试

**预期结果**：
- Goal 成功创建

- [ ] 打开创建 Goal 表单

- [ ] 验证新 area 自动选中

- [ ] 验证新 area 出现在 Areas 视图中

**预期结果**：
- Modal 弹出并正确显示创建表单
- 新 area 创建成功并自动选中
- Goal 关联到新 area

### 2.3 默认使用"未分类"

**前置条件**：如果实现了此功能

- [ ] 打开创建 Goal 表单
- [ ] 不选择任何 area（或 area 字段为空）

**预期结果**：
- Goal 默认关联到"未分类"

## 3. 删除 Area 测试

### 3.1 禁止删除"未分类"

- [ ] 打开 Areas 视图
- [ ] 找到"未分类"领域卡片

**预期结果**：

- UI 上删除按钮禁用或隐藏
- 如果尝试删除，显示明确的错误提示

### 3.2 删除无关联 Goals 的 Area

- [ ] 创建一个新 area（不关联任何 goal）
- [ ] 打开 Areas 视图
- [ ] 点击该 area 的删除按钮
- [ ] 验证直接删除成功（无需确认对话框，或显示简单确认）
- [ ] 验证 area 从列表中消失

**预期结果**：
- 删除成功
- Areas 视图立即更新

### 3.3 删除有关联 Goals 的 Area

- [ ] 选择一个有关联 goals 的 area
- [ ] 点击删除按钮
- [ ] 验证显示确认对话框
- [ ] 验证对话框中显示：
  - 受影响的 goals 数量
  - "这些目标将被移动到'未分类'"的提示
  - 受影响的 goals 列表（如果有）
- [ ] 点击取消，验证操作取消
- [ ] 再次点击删除按钮
- [ ] 点击确认删除
- [ ] 验证 area 被删除
- [ ] 验证原关联的 goals 现在显示为"未分类"

**预期结果**：
- 确认对话框显示正确信息
- 删除后 goals 自动移到"未分类"
- Goals 没有丢失
